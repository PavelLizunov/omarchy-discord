# Omacord video transport

Verdict: Extend the pinned Disgo transport and reuse the decoder. Cameras retain the main voice connection; Go Live screen viewing owns a separate authorized media connection, not another account.

This package is copied from `github.com/disgoorg/disgo/voice` at `v0.19.7-0.20260825183231-aa92366d296d`. Its original Apache-2.0 LICENSE is retained. Only the voice package is copied; the main gateway and public Discord models remain the existing dependency. Upstream tests were not copied; Omacord's voice integration checks exercise this local package.

Changes: receive-capable video Identify and H264-only codec advertisement, opcode 12 stream metadata and SSRC ownership, opcode 15 subscriptions, RTP marker/payload demultiplexing, transport-only H264 fragment decryption, larger UDP receive buffer, serialized outgoing encryption and encrypted RTCP PLI. Complete video frames go through the existing DAVE session after H264 depacketization. Audio retains its existing per-packet path. H264 negotiation and both receive filters share `H264PayloadType` (105) and advertise RTX106. The native receive codec catalog assigns AV1=101, H265=103, H264=105, VP8=107, VP9=109. A local Session Description describes the client's send codec, not every remote sender. Earlier RTP101 padding observations did not prove H264 and the previous assignment was incorrect. Transport tests cover RTP105 under both AEAD modes, preserve Opus DAVE authentication and do not send unsupported codecs into H264 decoding. Authenticated transport-cc delivery acknowledgements include padding probes; bounded receiver reports run on video arrival. RTX repair uses explicit opcode12 mappings, never guessed SSRC offsets; bounded H264 access-unit reordering and Generic NACK request missing primary sequences; padding-only packets advance sequence accounting without entering the decoder. Candidates are accepted only after frame authentication, and late repaired units cannot reverse accepted decoder order. Synthetic encrypted-frame decoding does not establish live MLS negotiation.

The video module watches one selected webcam or Go Live screen. `OpenMedia` uses the stream RTC server/channel and parent voice session, with a distinct DAVE group, one bounded handshake and no automatic retries. Stream closure and connection loss never issue a main voice-state update. A screen viewer must receive fresh stream metadata and an authenticated sender before decoding; cached credentials and synthetic frames are not live acceptance. Selected screen Opus audio uses the stream's transport and DAVE authentication and joins the existing call playback mixer; it has no new capture or playback process. Deafen and the sender's local volume/mute also apply to the screen audio. Close and stream loss stop this bounded decoder queue. The receive path does not capture devices or record incoming video, and supports only H264. The backend owns and reaps one FFmpeg decoder, with fixed pipe-only arguments and bounded output dimensions/queues/frame sizes. Close, Leave and backend teardown stop it. UI snapshots contain only a recent image in memory.

Local synthetic decoder/packet checks and offscreen UI evidence do not certify live Discord negotiation, remote webcam delivery or physical user acceptance. Historical upstream gateway heartbeat/lifecycle limitations remain outside this patch.

The UDP transport sends a cancellable 8-byte `0x1337CAFE` ping every five seconds after IP discovery. This maintains the NAT receive route independently of microphone mute and Opus discontinuous transmission (DTX), without sending microphone data or changing speaking state. Reopen cancels the previous socket ping; Close cancels the current one. Ping replies are filtered before RTP decoding. See https://docs.discord.food/topics/voice-connections#udp-ping .

Media stability fixes accept both documented `seq` and legacy `s` sequence envelopes, and send `seq_ack` for Gateway v8 Resume. The sender owns its cancellation context from construction and starts at most once; Close no longer depends on a DAVE callback occurring first. A standard ticker paces audio, speaking commands inherit cancellation, and failed speaking commands do not mark the transition successful. UDP writes have a finite deadline. Codec output buffers are resized, not merely given spare capacity, so passthrough copy operations do not truncate packets beyond the initial 512 bytes. Participant departure removes every owned SSRC, not just the first map entry. Audio sender gating uses `ShouldHoldFrames` where the DAVE adapter supplies it, distinguishing a stable version-0 session from an unfinished encrypted handshake. PLI writes have a finite deadline; receive-side periodic NACK/PLI scheduling is owned by the media engine, not blocked on a subsequent packet arrival.

The outbound Go Live path explicitly opts into one video source in Identify and H264 encoding in Select Protocol. Ready supplies the primary and RTX SSRCs; no source is guessed. Video RTP is marshalled with Pion, then uses the existing Discord AEAD boundary. Dedicated feedback reads authenticate RTCP before exposing PLI/FIR/NACK; sender reports use Pion serialization. The owning media layer handles native DAVE frame encryption, bounded retransmission cache and portal capture. Main-call media never starts capture implicitly.

Standard RTCP wire encoding is delegated to `github.com/pion/rtcp v1.2.20`: PLI, Generic NACK, receiver reports and transport-wide congestion-control reports. Discord AEAD framing, extension identifiers, arrival accounting and request budgets remain local. Duplicate transport sequences retain their first arrival time; reordered negative deltas use symmetric 250-microsecond rounding. The media engine delegates H.264 NAL reconstruction to `github.com/pion/rtp v1.10.6/codecs`, with strict aggregation/FU admission, bounded reordering and DAVE authentication still owned by Omacord.
