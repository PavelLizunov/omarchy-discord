# Text-only consumer review

## Scope and identity

- Baseline: upstream `215f0ad32fc32d83187e389f118bed4262778451` plus the
  installed Service path fallback/diagnostic patch saved before this change.
- Candidate: this uncommitted project, actual `ClientView.qml`, `SwitcherView.qml`,
  portable native controls and inert consumer models. Source hashes are returned
  by MCP for each render. This is direct self-review, not independent review.
- Host: Omarchy 4.0.4, Qt 6.11.2, QML Preview MCP/renderer 0.3.0,
  offscreen/software, locale ru_RU. No desktop capture or preview viewer.

## Evidence

PNG evidence is retained at `/tmp/opencode/discord-visual-20261001/`.
Inspected states: chat, narrow chat, light/narrow member pane, voice controls,
quick switcher, empty, loading, error, login, locally generated fixture QR.
Logical dimensions range 640×420 to 1040×680; DPR 1 and 2. Native geometry,
zero-radius theme behavior, text wrapping, selectable/copyable text and
alignment of timeline/composer were checked. The QR readiness condition waits
for actual Image.Ready. The first QR render was not accepted as evidence of
an image: the fixture was initially captured before its asynchronous load.

- MCP loading/diagnostics: PASS for the reviewed states, no mock import modules.
- PNG inspection: PASS for listed captures; live compositor placement is separate.
- Native design/anti-slop: text-first hierarchy, host palette/spacing, no glows or
  decorative media. Long footer hints intentionally elide. No universal theme
  contrast certification is claimed; the host palette remains user-owned.
- Interaction: offscreen Qt Quick Test exercises production keyboard/navigation,
  composer send/edit/reply, spoiler reveal, copy/open links, member toggle,
  login actions, voice chords and quick-switcher activation. Inert commands only.
- Media policy: Node executes the actual Service admission functions with a socket
  recorder. No cached media path, request queue or fetch_media command is produced.
- Security differential: views no longer access Quickshell, I/O or user credentials;
  token entry still clears before delegation, markup is escaped, remote open actions
  accept HTTP/HTTPS and execute discrete argv. Backend/authentication code unchanged.

## Controlled microbenchmark

30 simultaneously instantiated message rows; same text, 30 content updates,
offscreen/software Qt Quick Test, no media sources, three interleaved before/after
trials. Baseline has only its native UI imports adapted to the same portable
native controls. Both runs use the same process runner and workload.

| Trial | Variant | Wall s | CPU s | Peak RSS KiB | Update ms |
|---|---|---:|---:|---:|---:|
| 0 | before | 1.931 | 1.379 | 93892 | 603 |
| 0 | after | 1.797 | 1.294 | 87760 | 804 |
| 1 | before | 1.762 | 1.360 | 93772 | 689 |
| 1 | after | 1.732 | 1.265 | 88020 | 724 |
| 2 | before | 2.514 | 1.422 | 93748 | 887 |
| 2 | after | 1.798 | 1.296 | 87900 | 676 |

Medians: CPU 1.379 → 1.294 s; peak RSS 93772 → 87900 KiB.
Update 689 → 724 ms: **no confirmed response-time improvement**.
This is component-level evidence, not an authenticated Discord or shared-shell
benchmark. It does not measure GPU memory or physical energy.

## Computational follow-up

Observed with an inert JS call counter on the actual MessageRow renderer:
30 reaction-only updates re-ran Markdown 30 times while text stayed unchanged.
A primitive `rawContent` dependency now prevents those evaluations. The same
test records zero extra parses for the 30 updates, exactly one for an edit,
and one for a changed mention/theme context. The counter is nonreactive so it
cannot cause a binding loop. Final MCP output matches the pre-optimization PNG
byte-for-byte at 1040×680; actual 499×506 tiled width also fits the controls.

The 500-message rolling cap and previous-channel release remain intact.
Timeline synchronization and grouping are O(n) over loaded messages; replacing
them without measured need would risk scroll stability. Most service timers
are one-shot; keepalive is gated on disconnection, idle checks on the explicit
disconnect preference, typing expiry on active typing, QR countdown on QR view.
No event-loop sleeps or arbitrary debounce were added to user input.

Final checks: 29 Node cases, 16 Qt Quick Test cases, the media-admission check,
manifest validation and diff whitespace checks. Live textOnly=true, ready,
mediaQueued=0, mediaPending=0, backend PID retained with NRestarts=0. No new
authenticated message or voice call was initiated for acceptance.

User screenshot follow-up: the unknown voice profiles contain only a user id
in the backend snapshot (`voiceUser` intentionally falls back to ID when the
gateway member cache has no profile). Avatar images are intentionally absent
in text mode; blank occupant names were a separate UI defect. Shared userLabel
now selects display name, username, a known message-author name, or `User #id`.
The voice fixture includes all three cases, renders without media requests,
and the pure-function check validates each fallback. This does not fetch missing
profiles or claim the real user name is known.

## Limits

Real send/edit/delete and a new voice connection are not exercised by the agent.
Persistent scratchpad/monitor-hotplug placement is not covered by offscreen tests.
The generic MCP has no input API; Qt Quick Test provides separate interaction
evidence. Existing media cache files are retained; explicit links may download
media through the external system handler.
